# 把子牧的表达方法用于原创内容

本文件中的示范句和完整示范均为本次原创，用来展示方法；不是语料原文，也不是用户真实经历。来源分析见 [语言风格分析](style-analysis.md)。

## 1. 先确定内容，再选择语言

写稿前识别四件事：这篇要对谁说、解决哪一个具体问题、用户已经提供了哪些事实、观众最后应该理解或做什么。已有答案就沿用，不要求用户填完整问卷。

缺少主题时先问主题；缺少决定结论的实测、经历或产品事实时，不用自信口吻填空。可以先写已有依据的部分，或把未提供的事实改成明确的条件、假设示范。用户不希望提问时，写明必要假设后完成可完成的稿件。

本方法尤其适合教程、视觉演示和具体问题讲解。观点稿可以迁移“具体情境、条件变化、边界修正”；故事稿可以迁移“事件细节、受挫、重新理解”。不要为了像示范稿，把所有主题都改成“三招技巧”。

## 2. 从原理层面设计这一稿

### 找一个能承载问题的对象

“如何提高工作效率”太大，可以落到一张不知道先做什么的清单；“怎么做知识内容”太大，可以落到一段观众听完仍不会操作的教程。这个对象应与用户材料和受众相关，不是从原作者稿件中搬一尊雕像或一个老板。

开场可选：一个具体困境、一个对照、一个现场问题，或一项需要解释的现象。只有真正准备了对照内容时，才写“这是前后两种效果”。没有画面支持，就把差别用语言说清楚。

### 让每一层真正变化

先写最直接的一步；再检查它遇到什么限制；有必要才补第二种方法或更深解释。选择实际成立的层级，不预设必须三段、三个反转或三个技巧。

示意：

> 任务写得抽象 → 改成具体动作 → 仍然太大 → 拆出能开始的一步 → 信息不全 → 把补齐信息也写成动作。

这里每个转折都改变观众下一步的做法。如果只是换句话重复“要具体”，就删掉。

### 给变化起名字，补上理由

能通过实例理解的概念，可以在实例后点出；依赖全局理解的内容，先给简短总览。不要把“先演示后定义”设成硬规则。

判断句应说明适用场景。例如某种排版有助于识别，并不意味着所有页面都必须这样排。写技术内容时，确认因果再解释，别把语言顺畅当成事实正确。

### 选择结尾的力度

- 操作型：给出下一步或一个检查办法。
- 解释型：回到开头的问题，说明现在理解了什么。
- 审美或情绪型：沿正文的对象和变化引出一层感受。
- 故事型：让最后一个细节回应最初的处境。

没有自然关联时，停在内容完成的地方即可。“关注”“领取”“我已经整理好”只有用户确实需要、且对应资源存在时才写。

## 3. 六个维度怎样落到原创句子

| 维度 | 避免只学表面 | 更有效的原创处理 |
|---|---|---|
| 用词 | “这会显著提升专业性” | “把结论放在第一行，读者打开就能先知道你要说什么。”让动作和变化代替空泛评价 |
| 句式 | 每句开头都加“其实只需要” | 依据关系选择条件句、动作链或对比句；同一段不是每句都要同构 |
| 口头习惯 | 强塞“夯、拉完了、咱们下期见” | 在真正给替代方案时用“或者”，承认例外时用“当然” |
| 语气 | 把观众说成不懂事的小白 | 先承认当前做法能解决什么，再说明还卡在哪里 |
| 叙述 | 并列几个看似有关的技巧 | 让上一种方法的新限制引出下一种方法，保持核心问题不变 |
| 节奏 | 每四五个字就换行，或整段不停加逗号 | 动作连续时连着说；新主体、新条件、新层次开始时拆句 |

以下为关系示例，句子不作为固定开头库：

- **对象—动作—结果**：“一页里挤了五个结论。先留住最重要的那个，其余放到下一页，观众才知道这一页先看哪儿。”
- **先可用，再补限制**：“按日期存文件很容易上手。可你找的是某个客户时，还得一层层翻。给文件名补上客户名，搜索时就多了一条线索。”
- **条件变化**：“如果听众已经知道背景，开头可以直接给结论；第一次接触这个话题的人，则需要先知道你在解决什么问题。”
- **有限类比**：“目录像路标，告诉你信息在哪里；但路标写清楚了，不代表内容本身已经讲清楚。”
- **克制收束**：“清单里写下的，不只是要完成什么，还要有从哪儿开始。”

这些示例展示讲法，不是对所有情境都成立的保证。正式成稿要根据用户事实调整措辞和前提。

## 4. 完整原创示范：让待办事项更容易开始

### 普通提纲

列待办事项时要把目标具体化、把大任务分解、明确执行动作，避免写得太笼统。

### 运用表达方法后的示范稿

你打开待办清单，第一条是“准备汇报”。汇报要准备，可现在先打开哪份文件？清单没告诉你。

先把这一条换成“把本周的三个项目进度写下来”。不用一下想完整份汇报，你现在要做的，是把这三个项目列出来。

如果写到第二个项目，发现结果还没收到，就先别盯着空白页。再记下一步：“找同事确认交付日期。”缺信息这件事，也有了可以开始的动作。

等进度列齐，再决定哪些要展开讲、哪些一句带过。原来笼统的“准备汇报”，就变成了几步各有对象的事情。

试着看一眼你的下一条待办。如果写着“学习”或“整理”，补上要学哪一节、整理哪个文件夹。清单写到这一步，才真正有了下一步。

### 为什么这样写

开场用一条具体任务承载问题，避免泛泛讨论自律；“换成、列出来、确认、决定”交付实际动作；“信息没收到”构成真实分支；结尾回到清单和下一步，没有突然上升到人生态度。讲法借鉴动作链和条件推进，主题、例子及表达均重新组织。

### 不推荐的表面模仿

> 99%的人根本不会列清单！其实只需要三个小技巧，就能让你的效率直接起飞，夯爆了！不妨打破规则，让热爱照亮你的星辰大海。

问题不在于某个词绝对不能用，而在于没有交付方法，夸张效果无依据，热梗与主题关系弱，结尾也没有正文支撑。

## 5. 改稿：保留用户的事实与观点

先检查问题落在哪一层，再动相应部分：

| 原稿问题 | 优先修改 |
|---|---|
| 全是“专业、高效、高级” | 找出具体对象，补操作和能被识别的变化 |
| 好几个“但是”却没有新信息 | 删除重复转折，或补上真正不同的条件 |
| 连续讲术语，观众难以跟上 | 增加一个自有例子或适当类比，并明确局限 |
| 同一对象被不同代词混用 | 重新点名对象，避免“它、这个、那样”串错 |
| 越改越像原作者 | 换掉来自原稿的案例顺序、招牌比喻和句子，重新从用户观点搭内容 |
| 结尾突然抒情 | 回收正文对象，或直接结束在行动建议 |

改完说明真正改变了什么，例如“把抽象建议改成动作”“补了原来缺失的适用条件”。不要只给一个没有依据的“子牧相似度”分数。

## 6. 交付前做一次有目的的回读

暂时忽略连接词，只看内容是否仍能推进；检查观众能否理解每一步对什么做什么；把效果判断与真实依据对应起来；确认第一人称故事属于用户；判断这份稿单独听是否能理解。

文字分行只能帮助排稿，不等于已经录音试读。用户指定时长时，依据用户的真实语速或已有样音估计；没有样音，只能标注为估计，不把语料的字符中位数当成口播时长标准。

需要短版本时优先减少案例和旁支，保留一条完整的方法链。用户没有要求时，不额外生成标题、分镜、发布计划或多个版本。
